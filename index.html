What’s changed in OpenClaw

Easier to install. Still not safe by default.

OpenClaw 2.0 landed in August 2026 and the stable line has moved on since (v2026.11.x at the time of writing). The project is now run by the OpenClaw Foundation. Here is how that shapes what we plan to do.

Better

Setup is much simpler

Guided onboarding now looks for AI access you already have, tests that it works, and refuses network installs that would be exposed without authentication. We’ll spend our time on configuration and workflows, not on fighting installers.

Still on you

Hardening is opt-in

Docker or Podman sandboxing and command approvals exist, but they’re off by default. Making sure they’re on, and tuned so the agent stays useful, is a core part of our setup.

Better

Teams and shared sessions

Shared cloud sessions let colleagues work in the same agent session. OpenClaw’s own docs say that’s collaboration, not a security boundary. One Gateway is one trust domain. We plan to design team setups around that limit.

New risk

Agents can now write their own skills

OpenClaw can turn past conversations into reusable skills. That’s handy, but it means new, unreviewed code can appear on its own. We intend to review anything the agent writes before it’s allowed to run unattended.

Upgrades need care

Sessions moved into SQLite

2.0 migrates sessions and transcripts to a new store, and downgrading is awkward. Our plan is a verified backup before any upgrade and tested updates before we apply them to your system.

Better

ClawHub now scans uploads

Skills are checked with VirusTotal, but the maintainers themselves call that “not a silver bullet”. Malicious skills that rely on hidden instructions or staged downloads can slip through. That’s why we plan to skip the marketplace.

Why self-setups go wrong

Getting it running is the easy part now.

Getting a safe, useful, affordable agent is where people still struggle. The mistakes below are what we’re designing our service to prevent.

Skills safety · our intended approach

We plan to rebuild skills, not install them.

Most services scan or review ClawHub skills and then install them. The original author’s code still runs on your machine, and if the review missed something, you carry the risk.

We intend to take a different route. We read what a skill claims to do (send emails, track expenses, schedule meetings) and write our own implementation. The original code never enters your system.

This applies to skills your agent writes for itself too. We plan to review those before they can run without supervision.

An honest boundary: OpenClaw itself, and any official plugins we use, are still third-party software. We plan to run only official, pinned releases and to update them on a tested schedule. Skills are the part we write.

Our commitment: no ClawHub skill code in your deployment, and our own skills reviewed before they go live.

Why security comes first

Early risks were real. Some are fixed, some aren’t.

What’s improved: OpenClaw now blocks network installs that would be exposed without authentication, has a built-in security audit command, and ClawHub scans uploads with VirusTotal.

What still needs a human: sandboxing and approvals are off by default. One Gateway is one trust domain. Scanning can’t reliably catch malicious instructions hidden in skill text or fetched later.

What we plan to do: turn on the protections, keep skills in our own code, and re-check on a schedule. Security is part of the build, not an add-on.

For teams & IT environments

Running OpenClaw across a team?
Different conversation.

OpenClaw 2.0 makes shared sessions easy, but one Gateway is still one trust domain. People who shouldn’t see each other’s work need separate Gateways. NemoClaw and OpenShell add sandbox and network policy around agents, but NVIDIA’s own documentation says they’re not a multi-tenant control plane or an identity system. We plan to help teams work out what they actually need.

How we plan to differ

Managed OpenClaw hosting is now a crowded market, with dozens of providers. We don’t plan to be one more host. We intend to offer independent, hands-on advice and build work: which runtime fits (OpenClaw, NemoClaw-wrapped, or an alternative such as Hermes Agent), how to split trust domains, and how to keep skills under your control.
